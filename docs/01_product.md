# CRM-система для зуботехнической лаборатории

## 1. Описание продукта

### Продукт

Веб-система для управления заказами зуботехнической лаборатории и взаимодействия лаборатории с клиниками-партнёрами.

Система предназначена для цифровизации процесса обработки заказов: от создания заказа клиникой до выполнения работ техниками, завершения заказа и его выдачи клинике.

### Цель системы

Создать единую систему, в которой:

- клиники могут создавать и отслеживать свои заказы;
- администраторы могут управлять заказами и распределять работу между техниками;
- техники видят назначенные им работы и фиксируют конкретно выполненные услуги;
- история выполненных работ сохраняется для последующей отчётности и гарантийных случаев;
- файлы заказа (фотографии, сканы, STL, PDF и другие документы) хранятся централизованно в течение установленного периода;
- финансовая информация, включая цены, доступна только администраторам.

### Пользователи системы

Система предназначена для трёх основных категорий пользователей:

- **Администраторы лаборатории**
- **Зубные техники**
- **Клиники-партнёры**

---

## 2. Бизнес-проблема

Зуботехническая лаборатория работает примерно с 20 сотрудниками и большим количеством клиник-партнёров.

В процессе работы необходимо одновременно контролировать:

- поступающие заказы;
- сроки выполнения;
- услуги, входящие в каждый заказ;
- распределение заказов между техниками;
- выполнение отдельных услуг;
- файлы, связанные с заказами;
- текущий статус заказа;
- историю выполненных работ;
- взаимодействие с клиниками.

При отсутствии единой системы часть информации может храниться в разных местах, передаваться устно или через различные каналы связи. Это усложняет контроль сроков, распределение работы и последующую отчётность.

Особенно важна фиксация того, **какой техник и какую конкретно работу выполнил**, поскольку эта информация должна сохраняться для внутренней отчётности и возможных гарантийных случаев.

Дополнительной проблемой является необходимость хранить большое количество файлов: фотографии, сканы, STL-файлы, PDF и другие материалы, связанные с заказами.

При этом финансовая информация лаборатории, в частности цены на услуги, является конфиденциальной и не должна быть доступна техникам и клиникам.

---

## 3. Предлагаемое решение

Предлагается разработать веб-систему, которая объединяет клиники, администрацию лаборатории и зубных техников в едином процессе обработки заказов.

### Клиника

Клиника получает собственную учётную запись и может:

- создавать заказы;
- указывать данные пациента;
- указывать врача;
- выбирать необходимые услуги;
- указывать желаемый срок выполнения;
- добавлять комментарии;
- прикреплять необходимые файлы;
- просматривать созданные заказы;
- отслеживать статус заказа.

Клиника должна иметь доступ только к собственным заказам.

### Администратор

Администратор управляет производственным процессом лаборатории и может:

- просматривать все заказы;
- создавать и редактировать заказы;
- управлять клиниками;
- управлять техниками;
- управлять каталогом услуг;
- назначать одного или нескольких техников на заказ;
- контролировать выполнение работ;
- видеть цены и другую финансовую информацию;
- просматривать историю заказов;
- получать отчётность по выполненным работам.

### Техник

Техник получает доступ только к назначенным ему работам.

Он может:

- просматривать назначенные заказы;
- просматривать необходимые материалы и файлы;
- видеть информацию, необходимую для выполнения работы;
- отмечать конкретные услуги, которые он выполнил;
- добавлять комментарий к выполненной работе;
- изменять статус своей работы.

Цена заказа и другая финансовая информация не должны быть доступны технику.

### История выполнения работ

Каждая выполненная работа должна фиксироваться отдельно.

Система должна сохранять:

- заказ;
- конкретную услугу;
- техника, выполнившего работу;
- дату и время выполнения;
- комментарий;
- другую необходимую информацию.

История выполненных работ не должна исчезать при обычном изменении или завершении заказа.

Это необходимо для:

- внутренней отчётности;
- контроля работы техников;
- анализа выполненных услуг;
- гарантийных случаев.

### Работа с файлами

Файлы, связанные с заказом, должны храниться централизованно.

К таким файлам могут относиться:

- фотографии;
- сканы;
- STL-файлы;
- PDF;
- другие документы и материалы, необходимые для выполнения заказа.

Файлы должны храниться ограниченный период времени.

После окончания периода хранения файлы могут быть автоматически удалены, при этом основные сведения о заказе должны сохраняться для истории и гарантийных случаев.

---

## 4. Основной процесс работы

### 4.1. Создание заказа

Клиника создаёт новый заказ и указывает:

- пациента;
- клинику;
- врача;
- необходимые услуги;
- желаемый срок выполнения;
- комментарий;
- необходимые файлы.

После создания заказ получает статус `NEW`.

### 4.2. Обработка заказа администратором

Администратор проверяет поступивший заказ.

После проверки администратор может:

- принять заказ;
- изменить необходимые данные;
- назначить техника или нескольких техников;
- изменить статус заказа.

### 4.3. Выполнение заказа

Назначенный техник получает заказ в своём списке работ.

Техник выполняет назначенную работу и после её завершения обязан явно указать, **какую конкретно услугу он выполнил**.

Если один заказ содержит несколько услуг, разные услуги могут быть выполнены разными техниками.

### 4.4. Завершение заказа

После выполнения всех необходимых работ заказ может перейти в статус `READY`.

После выдачи работы клинике заказ переводится в соответствующий финальный статус.

### 4.5. История

Все важные изменения заказа должны сохраняться в истории.

История должна позволять определить:

- кто выполнил действие;
- какое действие было выполнено;
- когда оно было выполнено;
- какие данные изменились.

## 5. MVP

Первая версия системы должна содержать только функции, необходимые для полноценного рабочего процесса лаборатории.

### Входит в MVP

#### Пользователи и доступ
- Авторизация
- Роли пользователей
- Разграничение прав доступа
- Управление пользователями

#### Клиники
- Создание клиники
- Редактирование клиники
- Просмотр клиник
- Учёт пользователей клиники

#### Техники
- Создание техника
- Редактирование техника
- Просмотр техников
- Назначение техников на заказы

#### Услуги
- Каталог услуг
- Создание и редактирование услуг
- Минимальный срок выполнения услуги
- Цена услуги
- Ограничение доступа к ценам

#### Заказы
- Создание заказа
- Редактирование заказа
- Несколько услуг в одном заказе
- Назначение техников
- Статусы заказа
- Просмотр заказа
- Поиск и фильтрация заказов

#### Выполненные работы
- Фиксация конкретно выполненной услуги
- Фиксация техника
- Дата и время выполнения
- Комментарий
- История выполненных работ

#### Файлы
- Загрузка файлов
- Просмотр файлов
- Скачивание файлов
- Контроль доступа к файлам
- Хранение файлов установленный период
- Автоматическое удаление файлов после окончания периода хранения

#### История и отчётность
- История изменения статусов
- История выполненных работ
- Базовые отчёты по выполненным работам

#### Безопасность
- Авторизация
- Разграничение доступа по ролям
- Изоляция данных между клиниками
- Ограничение доступа к финансовой информации

---

## 6. Не входит в MVP

Следующие функции не являются необходимыми для первой рабочей версии:

- Мобильное приложение
- Интеграция с бухгалтерскими системами
- Интеграция с 1С
- Управление складом
- Учёт заработной платы
- Онлайн-оплата
- Telegram-бот
- SMS-рассылки
- AI-функции
- Сложная аналитика
- Сложная автоматизация распределения заказов
- Интеграция с внешним оборудованием

Эти функции могут быть рассмотрены после успешного запуска первой версии системы.

---

## 7. Основной критерий успешности MVP

Первая версия считается рабочей, если реальный заказ может пройти полный цикл:

Клиника создаёт заказ  
→ Администратор принимает заказ  
→ Администратор назначает техника  
→ Техник получает работу  
→ Техник фиксирует конкретно выполненные услуги  
→ Все необходимые работы завершены  
→ Заказ получает статус `READY`  
→ Работа выдана клинике  
→ История заказа и выполненных работ сохраняется.

При этом:

- клиника не имеет доступа к заказам других клиник;
- техник не имеет доступа к ценам;
- техник не имеет доступа к чужим заказам;
- история выполненных работ сохраняется;
- файлы доступны только авторизованным пользователям с соответствующими правами.
