# Роли и разрешения

## 1. Общие сведения

В системе предусмотрены три основные роли:

- `ADMIN` — администратор лаборатории
- `TECHNICIAN` — зубной техник
- `CLINIC` — представитель клиники

Права доступа определяются ролью пользователя.

Проверка прав должна выполняться на стороне backend.

Скрытие элементов интерфейса на frontend не является достаточной защитой.

---

# 2. ADMIN

## Назначение роли

Администратор управляет производственным процессом лаборатории, заказами, техниками, услугами и финансовой информацией.

Администратор имеет доступ ко всем рабочим данным системы.

# 3. TECHNICIAN

## Назначение роли

Техник получает доступ только к тем заказам, в которых он назначен исполнителем.

Основная задача техника — выполнить свою часть работы и зафиксировать конкретно выполненные услуги.

---

## Заказы

| Действие | Разрешено |
|---|---|
| Просматривать все заказы | Нет |
| Просматривать назначенные заказы | Да |
| Просматривать чужие заказы | Нет |
| Создавать заказ | Нет |
| Редактировать заказ | Нет |
| Изменять данные пациента | Нет |
| Изменять клинику | Нет |
| Изменять врача | Нет |
| Изменять услуги заказа | Нет |
| Изменять срок выполнения | Нет |
| Изменять комментарий заказа | Нет |
| Изменять статус всего заказа | Нет |
| Видеть статус заказа | Да |
| Видеть других техников этого заказа | Да |
| Видеть назначенных ему услуги | Да |

## Выполнение работы

| Действие | Разрешено |
|---|---|
| Открыть назначенный заказ | Да |
| Просматривать файлы заказа | Да |
| Скачать разрешённые файлы | Да |
| Отметить выполненную услугу | Да |
| Отметить несколько выполненных услуг | Да |
| Добавить комментарий к своей работе | Да |
| Изменить свою работу после закрытия | Нет |

| Повторно открыть закрытую работу | Нет |

Техник не может самостоятельно установить, что весь заказ завершён.

Он только закрывает свою часть работы.

Статус всего заказа `ЗАВЕРШЕНО` устанавливается системой после того, как последний назначенный техник закроет свою работу.

## Финансовая информация

Техник не имеет доступа к финансовой информации.

| Данные | Доступ |
|---|---|
| Цена услуги | Нет |
| Итоговая стоимость заказа | Нет |
| Расценка техника | Нет |
| Заработок по услуге | Нет |
| Заработок по заказу | Нет |
| Заработок других техников | Нет |
| Финансовые отчёты | Нет |

Это ограничение должно применяться на backend.

API не должен возвращать финансовые поля пользователю с ролью `TECHNICIAN`.

# 5. Доступ к файлам

Доступ к файлам определяется не только ролью, но и принадлежностью пользователя к заказу.

## ADMIN

Может просматривать файлы любого заказа.

## TECHNICIAN

Может просматривать файлы только заказов, в которых он назначен.

## CLINIC

Может просматривать файлы только собственных заказов.

Пользователь не должен иметь возможности получить файл другого заказа, изменив `order_id` или идентификатор файла в запросе.

Backend должен проверять:

1. существует ли файл;
2. существует ли заказ;
3. имеет ли пользователь право доступа к заказу;
4. имеет ли пользователь право доступа к конкретному файлу.

---
